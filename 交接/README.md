# 交接目录 —— 跨对话的状态传递

> **这个目录解决的问题**：Vibe Coding 工具的对话上下文有限。项目做到后期，代码量和讨论量远超一次对话能容纳的范围。
>
> **解决办法**：把"记忆"从**聊天记录**搬到**仓库文件**。聊天记录换个窗口就没了；仓库文件永久保存，还跟着 git 走。

---

## 三个文件，各管一件事

| 文件 | 作用 | 什么时候更新 |
|---|---|---|
| **`PROGRESS.md`** | 当前进度（**唯一权威状态**） | **每完成一个阶段** |
| **`DECISIONS.md`** | 已定的设计决策 + 技术陷阱 | 有新决策或踩到新坑时 |
| **`SESSION-PROMPT.md`** | 开新对话时复制粘贴的提示词 | 很少需要改 |

---

## 怎么用（三步）

### 1. 做完一个阶段

对 AI 说：

```
请把当前进度写进 交接/PROGRESS.md，然后提交推送。
```

### 2. 开新对话

打开 `SESSION-PROMPT.md`，复制「一、开新对话时说什么」那一整段，粘贴到新窗口。

### 3. 新对话的 AI 会自己读

那段提示词里明确要求了读哪几个文件、读完要复述什么。所以新 AI 一开口就能接上。

---

## 为什么 `DECISIONS.md` 特别重要

它记录的是**"为什么这么做"**，而不只是"做了什么"。

没有它，新对话的 AI 很可能会重复提一些**已经验证过行不通**的建议，例如：

- "我们把核心改动上限放宽一点吧" → 不行，见 D1
- "MOD 用 `mod:` 前缀做命名空间吧" → 不行，那个正则只允许 7 个固定前缀，见 D8
- "加一个新的第 5 难度吧" → 不行，模式和难度是绑死的，见 D3
- "往 `public/js/` 加个客户端文件吧" → 不行，会被上游测试遍历校验，见 D9

每一条都是实际读代码/实测得出的结论。**写下来就是为了不再踩第二次。**

---

## 这个目录不算"上游文件改动"

`交接/` 是新增目录，上游没有。所以它不会造成合并冲突，也不需要登记到 `mods/tools/mod-core-changes.json`。

---

## 万一 AI 没有主动读这些文件

直接把 `SESSION-PROMPT.md` 的提示词贴给它。提示词里写得很明确。

如果它读完之后理解还是有偏差，用「三、让 AI 在开始前先复述」那一段，让它先说一遍再动手。
