# 开新对话用的提示词

> 这个文件里全是**直接复制粘贴**的东西。
> 当一次对话的上下文快满的时候，或者你想换个窗口继续的时候，用这里的内容。

---

## 一、开新对话时说什么（最常用）

复制下面整段，粘贴到新对话的第一条消息里：

```
这是一个 MOD 系统开发项目，是 Stronghold-Protocol 的 fork（明日方舟同人游戏网页版）。

我的情况：我不太会写代码，全程依靠你来开发。上一次对话的上下文满了，所以新开
了这个窗口。项目状态都记录在仓库文件里，请先读文件再说话。

请按顺序读这四个文件：
1. 交接/PROGRESS.md    ← 当前进度（唯一权威状态）
2. 交接/DECISIONS.md   ← 已定的设计决策 + 技术陷阱（不要推翻）
3. docs/MODS.md        ← MOD 系统架构契约
4. GIT-手册.md         ← 我的 git 使用备忘（了解我和 git 的关系）

仓库位置：E:\new\Stronghold-Protocol - 副本

读完先告诉我这三件事，然后等我确认，不要直接开始写代码：
① 现在在哪个阶段
② 下一步具体该做什么
③ 有哪些必须遵守的规矩和不能碰的坑
```

---

## 二、阶段做到一半要换窗口时

如果 P1 做了一半（比如数据合并写完了但游戏内显示还没做），在**旧对话**里让 AI 先更新进度：

```
请把当前进度写进 交接/PROGRESS.md，包括：
- 这个阶段哪些做完了、哪些没做完
- 正在改的文件和改动思路
- 下一步该从哪继续
- 有什么没解决的问题
写完之后提交并推送（git add -A && git commit && git push）。
```

然后去新对话用**第一段**的提示词即可。新对话的 AI 读完 `PROGRESS.md` 就知道从哪继续。

---

## 三、让 AI 在开始前先复述（防止跑偏）

如果你担心新对话的 AI 理解错了，可以在第一段后面加这句：

```
在动手之前，请先用你自己的话复述一遍：
- 这个项目要达到什么目标
- 为什么我们坚持"不改原文件"这个原则
- 你打算怎么开始第一步
我确认之后你再动手。
```

---

## 四、上游更新了，要合并时说什么

当作者发布了新版本，你想把更新合并进来：

```
上游有新更新了，请帮我把更新合并进来。

请按 GIT-手册.md 第四节的流程操作：
1. 切到 master，从 upstream 拉取更新
2. 推送到 origin/master
3. 切回 modkit，把 master 合并进来
4. 跑 node --test，确认全绿
5. 如果 modkit-compat.test.js 报错，告诉我具体是哪个接口变了，
   并说明 MOD 层需要怎么跟着改

合并过程中如果有冲突，停下来告诉我，不要自己乱改。
```

## 五、对话太长了，想主动收缩时

如果你感觉对话变慢、或者 AI 开始"忘事"，主动说：

```
这次对话的上下文快满了，请做交接准备：
1. 更新 交接/PROGRESS.md：当前进度、未完成的部分、下一步
2. 如果有新的设计决策或踩到新的坑，追加到 交接/DECISIONS.md
3. 如果有新的上游文件改动，更新 mods/tools/mod-core-changes.json
4. 跑一次 node --test 确认状态健康
5. git add -A && git commit -m "..." && git push

做完告诉我，我就去开新对话。
```

---

## 六、想确认项目还健康时说什么

```
请帮我做一次项目体检：
1. node --test 跑完整测试套件，报告通过/失败数
2. node mods/tools/build-mods.mjs --check 校验 MOD 工具
3. git status 确认工作区干净
4. git log --oneline -5 看最近的提交
5. 对比本地和远端：git ls-remote --heads origin modkit
6. 统计对上游文件的改动数量（应该还是 1 个文件）

有任何异常直接告诉我。
```

---

## 七、为什么这样设计（给你自己看的）

**问题**：Vibe Coding 工具的对话上下文有限。项目做到 P3/P4 时，代码量和讨论量远超一次对话能容纳的范围。

**解决**：把"记忆"从**聊天记录**搬到**仓库文件**。

```
聊天记录  →  会溢出，换个窗口就没了
仓库文件  →  永久保存，还会跟着 git 走，甚至能在别的电脑上接着做
```

这就是为什么 `交接/` 目录里的文件比聊天记录重要得多。
**每完成一个阶段，一定要让 AI 更新 `PROGRESS.md`** —— 这是你唯一不会丢的东西。

**另一层保险**：`DECISIONS.md` 记录了"为什么这么做"。
新对话的 AI 如果不读它，很可能会提出"我们把核心改动放宽一点吧"或者
"用 `mod:` 前缀不就好了"之类的建议——这些坑都已经踩过了，写下来就是为了不再踩第二次。
